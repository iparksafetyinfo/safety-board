# 현장 상황판 (Field Situation Board)

건설현장 일일 작업투입을 **경보 중심**으로 관리하는 웹앱.
작업을 목록으로 나열하는 도구가 아니라, **위험 조합을 자동으로 찾아내 띄우는 상황판**입니다.

현장을 옮길 때는 `field.config.js` 한 파일만 고칩니다.

---

## 이 시스템의 성격

| | |
|---|---|
| 메인 화면 | 관제실형 **상황판** — 사무실 모니터에 띄워두고 보는 형태 |
| 판단 주체 | 사람이 목록을 훑는 게 아니라 **경보 엔진이 먼저 찾아냄** |
| 위치 표현 | **구간 × 공종 히트맵** + **설계도면 / 항공사진 전환형 현장도** |
| 입력 | 긴 폼이 아닌 **3단계 위저드** (위치 → 작업 → 점검) |
| 기록 | 카드가 아닌 **밀도 높은 표** — 그대로 엑셀로 나감 |
| 톤 | **HDC 공식 CI** — Charcoal Black / White / HDC Red |

## 경보 엔진 — 자동으로 잡아내는 6가지

작업을 등록하면 서로의 조합을 계산해서 위험을 찾습니다. **사람이 놓치는 건 개별 작업이 아니라 작업 사이의 관계**이기 때문입니다.

| 경보 | 조건 | 왜 위험한가 |
|---|---|---|
| **점검 미확인** | 필수 점검항목이 안 찍힌 채 작업중/대기 | 착수 전 확인 누락 |
| **동시작업** | 같은 구역·같은 층에서 **다른 업체**의 작업 시간이 겹침 | 신호 혼선, 책임 공백 |
| **중장비 밀집** | 같은 구간에서 굴착·운반·다짐 등 장비작업 시간 중복 | 협착·충돌 |
| **굴착 간섭** | 굴착·관부설 작업 시간에 **다른 업체** 작업이 같은 구간에 | 매몰·접촉 |
| **상하층 작업** | 같은 구역 **인접 층** 고위험 동시 진행 *(건축 현장 전용, 기본 꺼짐)* | 낙하물 |
| **인원 과밀** | 한 구역 동시 투입인원이 기준 초과 | 대피 동선 확보 불가 |
| **야간 작업** | 설정 시각 이후 종료 예정 | 조도·순찰 대상 |
| **기상** | 체감온도 폭염/한파, 강풍(양중작업 있으면 격상) | 온열질환, 양중 사고 |

임계값은 전부 `field.config.js`의 `alerts`, `shift`에서 조정합니다.

**토목 / 건축 전환** — `alerts.adjacentLevel` 을 `true` 로 바꾸면 상하층 경보가 켜집니다.
아파트 현장에서는 `labels` 를 `{ zone:"동", level:"층" }` 으로, `levels` 를 층 목록으로 바꾸면 그대로 건축용이 됩니다.

## 색상 규칙 — 반드시 지켜주세요

HDC 공식 CI를 그대로 적용했습니다.

| 색 | 코드 | 용도 |
|---|---|---|
| CHARCOAL BLACK | `#212121` (PANTONE 419C) | 기본 배경 |
| HDC WHITE | `#FFFFFF` | 본문 텍스트, 주요 버튼 |
| **HDC RED** | `#F01428` (PANTONE 185C) | **경보·고위험 전용** |
| COOL GRAY | `#A8A8AA` (Cool Gray 6) | 보조 텍스트 |
| SILVER | `#A7A9AB` (PANTONE 10077C) | 구분선, 소제목 |

**핵심 원칙: HDC RED는 위험을 뜻할 때만 씁니다.**

브랜드색이 곧 경고색이라는 게 이 팔레트의 장점입니다. 버튼이나 활성 탭 같은 평범한 UI 강조에 빨강을 쓰면, 정작 경보가 떴을 때 눈에 들어오지 않습니다. 그래서 UI 강조는 전부 **흰색·실버**로 처리했습니다. 새 기능을 붙일 때도 이 규칙을 지켜주세요.

중위험(`#F5A200`)과 일반(`#00A65A`)은 CI에 없는 색이라 **산업안전보건 신호색** 기준을 따로 적용했습니다. 위험 3단계는 색으로 즉시 구분돼야 하기 때문입니다.

CI 이미지는 두 가지를 넣어뒀습니다.

- `assets/ci-light.png` — 어두운 배경용 (흰 글자 + HDC RED 심볼) · 앱에서 사용
- `assets/ci-dark.png` — 밝은 배경용 (차콜 글자) · 인쇄·문서용

## 현장도 — 설계도면 · 항공사진 두 가지

우측 상단에서 **설계도면 / 항공사진**을 전환합니다. 두 이미지는 좌표계가 다르므로
**마커 위치도 각각 따로 저장**됩니다. 도면에서 옮겨도 항공사진 마커는 그대로입니다.

- **설계도면** — `C-C-005 공사계획평면도`(DWG)를 변환해 구역계·도로중심선·블럭 테두리만 남긴 것
- **항공사진** — 드론 정사영상에서 공사구역만 잘라낸 것

설계도면의 1·2구간 마커는 **도면의 구역계 폴리곤 중심을 계산해 미리 찍어뒀습니다.**
바로 쓸 수 있고, 옮기고 싶으면 위치지정으로 바꾸면 그 값이 우선합니다.

이 화면은 구역 마커를 찍는 곳이기도 합니다. **좌표는 앱 안에서 클릭으로 지정**하고 Firebase에 저장되므로, 설정 파일에 숫자를 적을 필요가 없습니다.

1. `현장도` 탭 → 우측 상단 **위치지정** (관리자 `own` 권한만)
2. 아래 줄에서 배치할 구역을 고르고 → 사진에서 그 위치를 클릭
3. 클릭하면 자동으로 다음 미지정 구역으로 넘어갑니다
4. 다 찍으면 **완료**

마커 위에서 **우클릭**하면 지정이 해제됩니다. 한 번 지정하면 모든 기기에 즉시 반영됩니다.

| 표시 | 의미 |
|---|---|
| 회색 빈 원 | 지정만 되고 당일 작업 없음 |
| 색 채워진 원 + 숫자 | 당일 작업 건수 (색 = 최고 위험등급) |
| 라벨의 `· N명` | 해당 구역 당일 투입 인원 |

마커를 클릭하면 그 구역의 당일 작업 목록이 아래에 펼쳐집니다.
**맞춤** 버튼은 사진 전체를 화면에 맞추고, `+` / `−` 로 확대해 세부를 봅니다.

### 이미지 교체 / 추가

`field.config.js` 의 `map.layers` 에 `{id, label, image}` 를 넣으면 탭이 늘어납니다.
이미지를 바꾸면 그 레이어의 좌표만 어긋나므로 **해당 레이어에서만 위치지정을 다시** 하면 됩니다.

`map.seed.{레이어}` 에 좌표를 적어두면 저장된 값이 없을 때 그 값을 씁니다.

### 설계도면(DWG)에서 현장도 만들기

원본 DWG는 `LibreDWG` 로 DXF 변환 후 `ezdxf` 로 렌더링했습니다. 다음 현장에서도 같은 방법을 씁니다.

```
dwg2dxf 도면.dwg                    # DWG → DXF
python3 로 '-구역계(대상지)' 레이어 폴리곤 추출  # 현장 경계
구역계 중심점 → 이미지 비율좌표 → map.seed 에 기록
```

**부수 효과**: 구역계 폴리곤에서 면적이 바로 나옵니다.
이 현장은 1구간 112,624㎡ · 2구간 337,291㎡ · 합계 **449,920㎡ (44.99ha)**.

```
├── index.html          화면 뼈대        ← 수정 불필요
├── board.css           디자인           ← 수정 불필요
├── board.js            로직·경보엔진     ← 수정 불필요 (중요)
├── field.config.js     ★ 현장 설정       ← 현장마다 이것만 수정
├── rules.json          Firebase 보안 규칙
├── manifest.json       앱 설치 정보
└── assets/
    ├── plan.jpg        설계도면 기반 현장도
    ├── site.jpg        드론 정사영상
    ├── ci-light.png    CI (어두운 배경용)
```

`board.js`를 고치기 시작하면 현장마다 코드가 갈라져서 재사용이 깨집니다.
기능을 바꾸고 싶으면 **설정 항목으로 뺄 수 있는지 먼저 검토**하세요.

## 새 현장 세팅

### 1단계 · Firebase (최초 1회, 이후 현장은 재사용)

1. [console.firebase.google.com](https://console.firebase.google.com) → 프로젝트 만들기
2. **Realtime Database** → 위치 `asia-southeast1` → **잠금 모드로 시작**
3. 규칙 탭 → `rules.json` 내용 붙여넣고 게시
4. Authentication → **이메일/비밀번호** 사용 설정
5. 프로젝트 설정 → 웹앱 추가 → SDK 설정값 복사 → `field.config.js`의 `firebase`에 붙여넣기

### 2단계 · 인원 등록

**첫 관리자는 자동으로 등록됩니다.** Authentication에서 계정을 만들고 그 계정으로 앱에 처음 접속하면,
인원 목록이 비어 있는 것을 확인하고 **본인을 `own`(관리자)으로 자동 등록**합니다.
보안 규칙이 "인원 목록이 비어 있을 때 딱 한 번"만 허용하므로, 그 뒤로는 잠깁니다.

두 번째 사람부터는 Realtime Database에서 직접 추가합니다.

```
field/{현장코드}/members/{UID}  =  "own"    ← 안전관리자 (전권)
field/{현장코드}/members/{UID}  =  "edit"   ← 작업 등록 담당
field/{현장코드}/members/{UID}  =  "view"   ← 열람 전용
```

| 등급 | 권한 |
|---|---|
| `own` | 전체 수정·삭제, 인원 등급 부여 |
| `edit` | 작업 등록, **본인이 등록한 것만** 수정·삭제 |
| `view` | 조회·엑셀만 |

> **members에 없는 계정은 데이터를 아예 못 읽습니다.** 보안 규칙에 그렇게 걸어뒀습니다.

### 3단계 · 현장 설정

`field.config.js`에서 채울 것:

- `field.code` — **현장마다 반드시 다르게.** DB가 이 값으로 갈립니다
- `field.name`, `field.org`
- `field.brand` — **HDC 공식 CI 색상. 임의로 바꾸지 마세요**
- `field.logo` — CI 이미지 경로 (어두운 배경용 `ci-light.png`)
- `labels` — 화면 용어. 토목 `{zone:"구간", level:"공종"}` / 건축 `{zone:"동", level:"층"}`
- `zones` — 히트맵 **가로축** (구간·공구·동)
- `levels` — 히트맵 **세로축** (토목은 공종, 건축은 층 — 건축이면 위→아래 순서로)
- `trades` — 세부 작업유형. `alerts.equipTrades`·`trenchTrades` 와 이름이 일치해야 경보가 작동합니다
- `vendors`, `checks`, `roles` — 현장 실정에 맞게
- `shift` — 근무 시간대와 야간 기준 시각
- `alerts` — 경보 임계값
- `geo` — 현장 위경도 (구글맵 우클릭)

> 건축 현장에서만: `levels` 순서가 곧 상하층 판정 기준이므로 순서를 뒤섞지 마세요.
> 토목 현장은 `adjacentLevel:false` 라 순서가 판정에 쓰이지 않습니다.

### 4단계 · 배포

GitHub 저장소에 올리고 Settings → Pages → Source를 `main`으로 지정.
`https://<계정>.github.io/<저장소>/` 로 접속됩니다.

사무실 모니터에서는 **F 키** 또는 좌측 하단 전체화면 버튼.
휴대폰은 공유 → 홈 화면에 추가.

## 자주 겪는 문제

| 증상 | 원인 / 해결 |
|---|---|
| 접속은 되는데 화면이 비어 있음 | `members`에 UID 미등록. 관리자에게 등급 부여 요청 |
| 첫 관리자 자동등록이 안 됨 | 이미 다른 사람이 먼저 접속해 `members`가 생성된 경우 |
| "저장 실패 — 권한을 확인하세요" | 등급이 `view`이거나 남의 기록을 수정하려는 경우 |
| 중장비 밀집 경보가 안 뜸 | `trades` 이름과 `alerts.equipTrades` 이름이 다름 |
| 상하층 경보가 안 뜸 | `alerts.adjacentLevel` 이 false (토목 기본값) |
| 현장도에 마커가 없음 | 아직 위치지정을 안 함. 관리자 권한으로 지정하세요 |
| 위치지정 버튼이 막힘 | `own` 권한만 가능합니다 |
| 기상정보 수신 불가 | 사내망이 외부 API 차단. `alerts`의 기상 경보만 동작 안 함 |
| 엑셀 버튼 무반응 | 사내망 CDN 차단. ExcelJS를 파일로 받아 함께 올리세요 |

## 주의

- Firebase 설정값이 노출되는 것은 정상입니다. **보안은 전적으로 `rules.json`에 달려 있습니다.**
- 규칙 변경 후에는 Firebase 콘솔의 **규칙 시뮬레이터**로 반드시 검증하세요.
- 관리자 비밀번호를 코드에 넣는 방식은 쓰지 않습니다. 권한은 `members`로만 관리합니다.
