# 현장 상황판 (Field Situation Board)

건설현장 일일 작업투입을 **경보 중심**으로 관리하는 웹앱.
작업을 목록으로 나열하는 도구가 아니라, **위험 조합을 자동으로 찾아내 띄우는 상황판**입니다.

현장을 옮길 때는 `field.config.js` 한 파일만 고칩니다.

---

## 이 시스템의 성격

| | |
|---|---|
| 메인 화면 | **현장 현황도** — 전경사진 위에 획지 경계를 얹고, 작업이 있는 획지를 위험등급 색으로 칠합니다 |
| 판단 주체 | 사람이 목록을 훑는 게 아니라 **경보 엔진이 먼저 찾아냄** |
| 위치 표현 | **획지(구역) 단위** — 설계도면에서 뽑은 18개 획지를 전경사진에 정렬 |
| 입력 | **2단계 위저드** (위치 → 작업). 전날 것 그대로 복사 가능 |
| 기록 | 카드가 아닌 **밀도 높은 표** — 그대로 엑셀로 나감 |
| 톤 | **HDC 공식 CI** — Charcoal Black / White / HDC Red |

---

## 경보 엔진 — 자동으로 잡아내는 것들

작업을 등록하면 서로의 조합을 계산해서 위험을 찾습니다. **사람이 놓치는 건 개별 작업이 아니라 작업 사이의 관계**이기 때문입니다.

| 경보 | 조건 | 왜 위험한가 |
|---|---|---|
| **동시작업** | 같은 구역에서 **다른 업체**의 작업 시간이 겹침 | 신호 혼선, 책임 공백 |
| **중장비 밀집** | 같은 구역에서 굴착·운반·다짐 등 장비작업 시간 중복 | 협착·충돌 |
| **굴착 간섭** | 굴착·관부설 시간에 **다른 업체** 작업이 같은 구역에 | 매몰·접촉 |
| **반려 작업 진행** | 원청이 반려한 작업이 당일에 살아 있음 | 시정 없이 착수 |
| **미승인 작업** | 원청 결재 전 작업이 당일에 잡혀 있음 | 검토 누락 |
| **익일 작업 미제출** | 협력사가 익일분을 마감까지 안 올림 | 다음날 파악 불가 |
| **인원 과밀** | 한 구역 동시 투입인원이 기준 초과 | 대피 동선 확보 불가 |
| **야간 작업** | 설정 시각 이후 종료 예정 | 조도·순찰 대상 |
| **기상** | 체감온도 폭염/한파, 강풍(양중작업 있으면 격상) | 온열질환, 양중 사고 |
| **상하층 작업** | 같은 구역 **인접 층** 고위험 동시 진행 *(건축 현장 전용, 기본 꺼짐)* | 낙하물 |

임계값은 전부 `field.config.js` 의 `alerts`, `shift`, `submission` 에서 조정합니다.

**토목 / 건축 전환** — `alerts.adjacentLevel` 을 `true` 로 바꾸면 상하층 경보가 켜집니다.

## 화면 구성

| 화면 | 누가 | 무엇을 |
|---|---|---|
| **현황판** | 전원 | 지표 6종 + **현장 현황도** + 경보 + 구역·공종 분포 + 시간대별 투입 |
| **작업투입** | 원청·협력사 | 2단계 입력. 제출 마감 카운트다운, 전일 복사, 지도에서 구역 선택 |
| **제출현황** | 원청 | 업체별 제출 여부 → 건별 **승인·반려**, **위험등급 지정** |
| **통계** | 전원 | 최근 2주/30일/90일 투입인원·고위험 추이, 업체·공종·구역·경보 순위 |
| **기록** | 전원 | 전체 표 + 검색·필터 + **엑셀** (결재·반려사유 포함) |
| **인원** | 원청 | 계정별 권한·업체 지정 (콘솔 안 들어가도 됨) |
| **작업일보** | 전원 | 날짜 골라 **A4 인쇄 / PDF 저장** — 아침 회의용 |

| SILVER | `#A7A9AB` (PANTONE 10077C) | 구분선, 소제목 |

**핵심 원칙: HDC RED는 위험을 뜻할 때만 씁니다.**

브랜드색이 곧 경고색이라는 게 이 팔레트의 장점입니다. 버튼이나 활성 탭 같은 평범한 UI 강조에 빨강을 쓰면, 정작 경보가 떴을 때 눈에 들어오지 않습니다. 그래서 UI 강조는 전부 **흰색·실버**로 처리했습니다. 새 기능을 붙일 때도 이 규칙을 지켜주세요.

중위험(`#F5A200`)과 일반(`#00A65A`)은 CI에 없는 색이라 **산업안전보건 신호색** 기준을 따로 적용했습니다. 위험 3단계는 색으로 즉시 구분돼야 하기 때문입니다.

CI 이미지는 두 가지를 넣어뒀습니다.

- `assets/ci-light.png` — 어두운 배경용 (흰 글자 + HDC RED 심볼) · 앱에서 사용
- `assets/ci-dark.png` — 밝은 배경용 (차콜 글자) · 인쇄·문서용

## 현장도 — 전경사진 + 획지

메인 화면입니다. 전경사진 한 장 위에 설계도면에서 뽑은 **획지 경계 18개**를 얹습니다.

- 작업이 있는 획지는 **위험등급 색**으로 칠해지고, 이름표 아래에 `건수 · 인원`이 붙습니다
- 획지를 누르면 그 구역의 당일 작업이 펼쳐집니다
- 화면에서 작게 잡히는 획지는 이름표를 자동으로 숨겨 글자가 겹치지 않습니다
- 배율은 **맞춤(100%) 기준 25 ~ 600%**

### 도면 맞추기

설계도면은 *앞으로 만들 것*이고 전경사진은 *지금의 땅*이라, 자동 정렬로는 완벽히 겹치지 않습니다.
그래서 **눈으로 한 번 맞추고 저장**하는 방식을 씁니다.

`현황판 → 도면 맞추기` (원청 계정만)

| 조작 | 방법 |
|---|---|
| 이동 | 사진 위를 끌기 / ← → ↑ ↓ |
| 크기 | 마우스 휠 / − + |
| 회전 | ↺ ↻ |
| 크게 움직이기 | 버튼 + `Shift` |

저장하면 `field/{코드}/fit` 에 들어가 **모든 사람 화면에 같이 적용**됩니다. 한 번만 하면 됩니다.

> 기준 잡기 좋은 곳은 경계가 뚜렷한 큰 획지입니다. 그거 하나 맞으면 나머지가 따라옵니다.

### 사진 교체

`field.config.js` 의 `map.image` 를 바꾸면 됩니다. 단, **사진이 바뀌면 획지 좌표(`map.zones`)도 다시 계산**해야 합니다.
좌표는 사진 가로·세로를 0~1 로 본 비율값입니다.

### 설계도면(DWG)에서 획지 뽑기

1. DWG → DXF 변환 (`dwg2dxf`, LibreDWG)
2. `블럭 테두리` + `0_시설선` + `c-포장선` + `-구역계(대상지)` 레이어의 선을 모아 폴리곤화(shapely `polygonize`)
3. `00_text(시설명)` 레이어의 텍스트 좌표가 들어가는 폴리곤에 그 이름을 붙임
4. 전경사진에 정렬 → 0~1 비율 좌표로 변환해 `map.zones` 에 기록

*이번 현장에서는 이 방법으로 18개 획지(의료시설·공동주택1/2·혁신의료연구단지·바이오융합복합단지·초등학교·근린공원1~3·경관녹지·주차장·준주거 등)를 뽑았습니다.*

## 파일 구조

```
├── index.html          화면 뼈대        ← 수정 불필요
├── board.css           디자인           ← 수정 불필요
├── board.js            로직·경보엔진     ← 수정 불필요 (중요)
├── field.config.js     ★ 현장 설정       ← 현장마다 이것만 수정
├── rules.json          Firebase 보안 규칙
├── manifest.json       앱 설치 정보
├── site2.jpg           전경사진 (획지 정렬 완료본)
├── ci-light.png        CI (어두운 배경용)
├── ci-dark.png         CI (밝은 배경용)
├── icon-*.png          앱 아이콘
├── 협력사_계정등록_절차서.md
└── members-양식.json    여러 계정을 한 번에 넣을 때
```

**캐시** — `index.html` 에서 css·js 주소에 `?v=날짜시각` 을 붙입니다.
파일을 고쳐 올릴 때 이 값을 같이 바꾸면, 사용자가 강제 새로고침을 하지 않아도 새 버전이 적용됩니다.

`board.js`를 고치기 시작하면 현장마다 코드가 갈라져서 재사용이 깨집니다.
기능을 바꾸고 싶으면 **설정 항목으로 뺄 수 있는지 먼저 검토**하세요.

## 새 현장 세팅

### 1단계 · Firebase (최초 1회, 이후 현장은 재사용)

1. [console.firebase.google.com](https://console.firebase.google.com) → 프로젝트 만들기
2. **Realtime Database** → 위치 `asia-southeast1` → **잠금 모드로 시작**
3. 규칙 탭 → `rules.json` 내용 붙여넣고 게시
4. Authentication → **이메일/비밀번호** 사용 설정
5. 프로젝트 설정 → 웹앱 추가 → SDK 설정값 복사 → `field.config.js`의 `firebase`에 붙여넣기

### 2단계 · 인원 등록

**첫 관리자는 자동으로 등록됩니다.** Authentication에서 계정을 만들고 그 계정으로 앱에 처음 접속하면,
인원 목록이 비어 있는 것을 확인하고 **본인을 `own`(관리자)으로 자동 등록**합니다.
보안 규칙이 "인원 목록이 비어 있을 때 딱 한 번"만 허용하므로, 그 뒤로는 잠깁니다.

두 번째 사람부터는 Realtime Database에서 직접 추가합니다.

원청(우리) 계정은 문자열 하나로 충분합니다.

```
field/{현장코드}/members/{UID}  =  "own"    ← 원청 안전관리자 (전권·결재)
field/{현장코드}/members/{UID}  =  "view"   ← 열람 전용
```

**협력사 계정은 업체를 계정에 고정합니다.** 문자열 대신 객체로 넣습니다.

```
field/{현장코드}/members/{UID}
    rank   : "edit"
    vendor : "○○건설"      ← field.config.js 의 vendors 에 있는 이름과 정확히 일치
    name   : "김반장"        ← (선택)
```

이렇게 넣으면 그 계정은 **작업투입 화면의 업체 칸이 ○○건설로 고정·잠김** 상태가 되고,
다른 업체 이름으로는 등록 자체가 불가능합니다.

| 등급 | 권한 |
|---|---|
| `own` | 전체 수정·삭제, 인원 등급 부여 |
| `edit` | 작업 등록, **본인이 등록한 것만** 수정·삭제 |
| `view` | 조회·엑셀만 |

> **members에 없는 계정은 데이터를 아예 못 읽습니다.** 보안 규칙에 그렇게 걸어뒀습니다.

> 협력사 계정을 실제로 만드는 순서는 **`협력사_계정등록_절차서.md`** 에 화면 순서대로 정리해뒀습니다.
> 여러 곳을 한 번에 넣을 때는 `members-양식.json` 을 쓰세요.

### 2-1단계 · 원청 ↔ 협력사 운영 방식

이 시스템은 **협력사가 전날 올리고, 원청이 당일 아침 한눈에 보는** 구조입니다.

| 시점 | 누가 | 무엇을 |
|---|---|---|
| 전날 (기한 `submission.dueHour`, 기본 17시) | 협력사 (`edit`) | 익일 작업을 [작업투입]으로 등록 |
| 전날 저녁 | 원청 (`own`) | [제출현황]에서 업체별 제출 여부 확인 → **승인 / 반려** |
| 당일 | 전원 | [상황판]이 **당일 작업**을 띄움 |

- **[제출현황]** — 날짜는 기본이 **익일**입니다. 업체별로 `미제출 / 검토 대기 / 승인 완료 / 반려 포함` 이 뜨고,
  [상세]에서 건별로 승인·반려합니다. 반려할 때 사유를 적으면 협력사 화면에 그대로 보입니다.
- **협력사 화면** — [기록]의 기본 범위가 **익일(제출분)** 로 잡혀서, 본인이 올린 건과 결재 결과·반려 사유를 바로 봅니다.
- **반려된 작업이 당일에 살아 있으면** 상황판에 「반려 작업 진행」 경보가, 결재가 안 끝난 건이 있으면 「미승인 작업」 경보가 뜹니다.
- 승인을 쓰지 않고 제출 여부만 보고 싶으면 `submission.requireApproval` 을 `false` 로 둡니다.
- 등록된 작업을 협력사가 수정하면 **결재는 자동으로 초기화**되어 다시 검토 대기가 됩니다.

### 3단계 · 현장 설정

`field.config.js`에서 채울 것:

- `field.code` — **현장마다 반드시 다르게.** DB가 이 값으로 갈립니다
- `field.name`, `field.org`
- `field.brand` — **HDC 공식 CI 색상. 임의로 바꾸지 마세요**
- `field.logo` — CI 이미지 경로 (어두운 배경용 `ci-light.png`)
- `labels` — 화면 용어. 토목 `{zone:"구간", level:"공종"}` / 건축 `{zone:"동", level:"층"}`
- `zones` — 히트맵 **가로축** (구간·공구·동)
- `levels` — 히트맵 **세로축** (토목은 공종, 건축은 층 — 건축이면 위→아래 순서로)
- `trades` — 세부 작업유형. `alerts.equipTrades`·`trenchTrades` 와 이름이 일치해야 경보가 작동합니다
- `vendors`, `checks`, `roles` — 현장 실정에 맞게
- `shift` — 근무 시간대와 야간 기준 시각
- `alerts` — 경보 임계값
- `geo` — 현장 위경도 (구글맵 우클릭)

> 건축 현장에서만: `levels` 순서가 곧 상하층 판정 기준이므로 순서를 뒤섞지 마세요.
> 토목 현장은 `adjacentLevel:false` 라 순서가 판정에 쓰이지 않습니다.

### 4단계 · 배포

GitHub 저장소에 올리고 Settings → Pages → Source를 `main`으로 지정.
`https://<계정>.github.io/<저장소>/` 로 접속됩니다.

사무실 모니터에서는 **F 키** 또는 좌측 하단 전체화면 버튼.
휴대폰은 공유 → 홈 화면에 추가.

| `1` `2` `3` `4` `5` | 현황판 / 작업투입 / 제출현황 / 통계 / 기록 |
| `F` | 전체화면 |

히트맵 셀을 누르면 해당 위치가 표시되고, 표에서 **수정·삭제**할 수 있습니다.

## 자주 겪는 문제

| 증상 | 원인 / 해결 |
|---|---|
| 접속은 되는데 화면이 비어 있음 | `members`에 UID 미등록. 관리자에게 등급 부여 요청 |
| 첫 관리자 자동등록이 안 됨 | 이미 다른 사람이 먼저 접속해 `members`가 생성된 경우 |
| "저장 실패 — 권한을 확인하세요" | 등급이 `view`이거나 남의 기록을 수정하려는 경우 |
| 중장비 밀집 경보가 안 뜸 | `trades` 이름과 `alerts.equipTrades` 이름이 다름 |
| 상하층 경보가 안 뜸 | `alerts.adjacentLevel` 이 false (토목 기본값) |
| 현장도에 마커가 없음 | 아직 위치지정을 안 함. 관리자 권한으로 지정하세요 |
| 위치지정 버튼이 막힘 | `own` 권한만 가능합니다 |
| 기상정보 수신 불가 | 사내망이 외부 API 차단. `alerts`의 기상 경보만 동작 안 함 |
| 엑셀 버튼 무반응 | 사내망 CDN 차단. ExcelJS를 파일로 받아 함께 올리세요 |

## 주의
